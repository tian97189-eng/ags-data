# 2026-09-01

## build-apk.bat PowerShell 调 java 的 -D 参数被吞（v5 修复，提交待定）

用户重跑 build-apk.bat 报错 `[6/7] Building APK`：

```
错误: 找不到或无法加载主类 .gradle.appname=gradlew
原因: java.lang.ClassNotFoundException: /gradle/appname=gradlew
```

**根因**：第 82 行用 PowerShell 的 `&` 调用 java.exe，但 PowerShell 会把以 `-` 开头的参数（如 `-Dorg.gradle.appname=gradlew`）当成自己的 cmdlet 参数尝试绑定；解析失败时把 `-D` 前缀吃掉，java 收到的是 `.gradle.appname=gradlew`（没有 `-D`），于是把它当成了"主类名"→ ClassNotFoundException。

**修复**：在 `& 'java.exe'` 后加 `--%`（PowerShell stop-parsing token），告诉 PowerShell「从这开始所有参数原样传给外部程序，不要再做参数绑定」；同时把 classpath 路径的双引号改对（`--%` 后单引号不会被解析为引号，双引号才会被 Win32 CommandLineToArgvW 当成 token 引号）。另外去掉了原来的 `2>&1`（`--%` 模式下 PowerShell 重定向语法不再被识别，会被当成 java 参数；gradle 已用 `--console=plain`，主要错误也走 stdout）。

**验证**：等用户重跑 build-apk.bat 确认成功。
