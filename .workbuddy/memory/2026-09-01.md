# 2026-09-01

## build-apk.bat PowerShell 调 java 的 -D 参数被吞（v5 修复，提交待定）

用户重跑 build-apk.bat 报错 `[6/7] Building APK`：

```
错误: 找不到或无法加载主类 .gradle.appname=gradlew
原因: java.lang.ClassNotFoundException: /gradle/appname=gradlew
```

**根因**：第 82 行用 PowerShell 的 `&` 调用 java.exe，但 PowerShell 会把以 `-` 开头的参数（如 `-Dorg.gradle.appname=gradlew`）当成自己的 cmdlet 参数尝试绑定；解析失败时把 `-D` 前缀吃掉，java 收到的是 `.gradle.appname=gradlew`（没有 `-D`），于是把它当成了"主类名"→ ClassNotFoundException。

**修复**：在 `& 'java.exe'` 后加 `--%`（PowerShell stop-parsing token），告诉 PowerShell「从这开始所有参数原样传给外部程序，不要再做参数绑定」；同时把 classpath 路径的双引号改对（`--%` 后单引号不会被解析为引号，双引号才会被 Win32 CommandLineToArgvW 当成 token 引号）。另外去掉了原来的 `2>&1`（`--%` 模式下 PowerShell 重定向语法不再被识别，会被当成 java 参数；gradle 已用 `--console=plain`，主要错误也走 stdout）。

**验证**：等用户重跑 build-apk.bat 确认成功。

## 修复后仍有问题：gradle 实际没跑（12:27 用户反馈"运行成功但桌面无 APK"）

用户重跑后反馈"运行成功了，但是桌面没有 AGS-data-app.apk"。排查：
- build-log.txt（12:26:48）内容停在 [5/7] cap sync 完成，**完全没有 [6/7] gradle 输出**
- `C:\Users\sky\ags-build2\android\app\build\outputs\apk\release\app-release.apk` 时间戳仍是昨天 21:10（旧文件）
- gradle daemon 日志也全是昨天的 → **[6/7] 的 java 根本没跑起来**

**根因（v5 新坑）**：我在上轮修复里把路径从单引号改成了 `\"...\"` 双引号。但 **cmd.exe 没有 `\"` 转义**——cmd 原样把 `\"` 传给 PowerShell，PowerShell 把 `\"` 解析成字面 `\` + `"`，结果是 classpath 变成 `\C:\Users\...\jar\`（开头结尾多反斜杠）→ java 找不到 GradleMain → 启动失败（stderr 不进 Tee 日志，所以日志看不到）。

**v6 修复**：路径全部不含空格 → **`--%` 模式下直接裸写路径、不加任何引号**，彻底绕开 cmd/PS 的引号传递问题。
- 验证：bash 里 `java.exe -Dorg.gradle.appname=gradlew -classpath C:\Users\sky\gradle-dist\gradle-8.14.3\lib\gradle-launcher-8.14.3.jar org.gradle.launcher.GradleMain --version` **成功输出 Gradle 8.14.3**（jar 路径+主类名正确）。
- 注意：`--%` 后路径若含空格会挂（当前路径无空格）；以后若换目录需改用 -EncodedCommand 或 .ps1 文件方案。
- 教训：**cmd → powershell -Command 传参时，内层双引号要用 `\"` 是错的（cmd 不转义）**；要么路径无空格不加引号，要么用 EncodedCommand/ps1 文件。这个坑记入 MEMORY.md。

## v7：弃用 cmd 内嵌 PS 命令串，改为 .ps1 脚本（12:30）

用户重跑 v6 后报错：
```
'换行符?token' 不是内部或外部命令
'hell' 不是内部或外部命令
Unrecognized option: --\Users\sky\gradle-dist\gradle-8.14.3\lib\gradle-launcher-8.14.3.jar
Error: Could not create the Java Virtual Machine.
```
**根因**：PowerShell 5.1 在 cmd 的 `-Command "..."` 字符串模式下，`--%` stop-parsing **行为不稳定**——PS 把 token 错误重组，把 `-classpath` 后面的内容吃成了 `--\Users\sky\...`（双横杠+反斜杠）传给 java；还出现了 "换行符?token"、"hell" 等被 cmd 当独立命令名尝试执行的乱码 token。

**v7 修复**：**完全弃用"cmd 内嵌 PS 命令串"这种脆弱写法**，改用独立 `.ps1` 脚本：
- 新建 `scripts\build-gradle.ps1`：里面写 `& 'java.exe' --% -Dorg.gradle.appname=gradlew -classpath ... GradleMain assembleRelease ... | Tee-Object -Append -FilePath log.txt`
- build-apk.bat [6/7] 改为 `powershell -NoProfile -ExecutionPolicy Bypass -File "%SRC%scripts\build-gradle.ps1"`
- PowerShell 在脚本文件模式下正常解析，`--%` 按 PS 解析器规则稳定工作；cmd 不参与 PowerShell 命令字符串的引号传递，彻底绕开之前所有引号/`-D` 吞掉的坑。
- 注意：`.ps1` 文件里 `--%` 后所有 token 必须字面量（PS 在 stop-parsing 模式下不展开变量、不解析引号），路径全部写死。
- **教训（写进 MEMORY.md）**：Windows PowerShell 5.1 在 cmd `-Command "..."` 字符串里使用 `--%` 行为不可靠；要把 PS 命令写到独立 `.ps1` 文件再 `powershell -File` 执行。
