
## 污泥浓度（MLSS）分次保存改造（16:24 用户报"分3天测一次填完才能保存"）
**问题**：M1（滤纸重）+ M2（滤纸+泥重）当天测，M3（坩埚重）次日，M4（灼烧后+坩埚重）第次）天）测。现状 handleAdd 要求 5 字段全填才能保存，用户必须等 3 天集齐再录。
**方案**：handleAdd → handleUpsert 按 (date+paperNo) 增/改：
- 任意字段可选填，至少填 1 个重量值即可保存
- update 分支**只写非空字段**（已填字段保留）
- computeMLSS 改写：容忍分次（M1/M2/V 齐就算 mlss，M3/M4 齐才算 mlvss）
- compute 用 merged 值（输入框空时 fallback 到 db 已有）
- 输入区加说明文案 + 按钮改"保存（按日期+编号自动合并）"
- 历史卡片加"已填 N/5"状态条 + "待补"提示 + "补充"按钮（一键载入到输入区继续填剩余字段）
- 删除 paperNo 不在 schema 索引里：where('date').equals + toArray().find() 替代 where('paperNo')
**测试踩坑**：
1. paperNo 不在索引 → SchemaError，改用 toArray().find()
2. React state 时序：fireEvent.change 后 click，闭包拿旧 state → 加 waitFor 检查 input.value 已落定才 click
3. handleUpsert merged 引用 existing（TDZ）→ existing 查询提前到 merged 计算前
4. getByText '补充' 多个（桌面表格 + 手机卡片）→ getAllByText
5. V 默认值 15 仍写入（产品预填）→ 测试期望接受 v=15
**结果**：测试+5（493 全过）；commit 037e13b；用户需重打 APK

**粒径（ParticleSize）原本就支持分次**：handleSaveRow 现状是"任一字段非空就 upsert"，只是用户没意识到（已有说明文字"可只填一个，会自动保存"）。本次不动。
